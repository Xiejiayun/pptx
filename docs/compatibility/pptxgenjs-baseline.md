# PptxGenJS 4.x conformance baseline

基线版本：`4.0.1`；允许范围：`^4.0.1`。

WP0 只依赖以下公开表面：

- `new PptxGenJS()`。
- `addSlide()` 以及公开的 slide 创建 API。
- `write({ outputType: 'nodebuffer' })` / `writeFile({ fileName })` 产生标准 PPTX。

验证样例包含文本、形状、主题和 slide relationships。PptxGenJS 4.0.1 生成的真实文件可由 `PptxDocument.open()` 导入、局部修改标题，并由 LibreOffice headless 无修复地打开和导出。

adapter 不读取 `_slides` 等私有字段。后续 peer-range conformance test 会对 `^4.0.1` 的最低版本和当前最新兼容版本运行同一组输出导入用例。

### Shape simple shadow

Strict `ShapeShadow`、`AddShapeOptions.shadow` 与 `ShapeModel.shadow` 支持唯一 direct `a:outerShdw` / `a:innerShdw` 的 create/read/whole-replace/clear。两个 kind 均支持 sRGB/theme color、量化到 `1/100000` 的 `0..1` opacity、量化到 1 EMU 的 `0..100pt` blur 与 `0..200pt` distance，以及量化到 `1/60000°` 的 `0 <= angle < 360`；outer 另支持 `rotateWithShape`。Omitted fields 使用 PptxGenJS 4.0.1 真实 shape output defaults：black、0.75、8pt、270°、4pt 和 outer rotate false；native 保留 explicit zero。输入在 mutation 前深度脱离，getter snapshot detached/deep-frozen；same-value exact no-op，same-kind edit patch owned spans，kind switch 只替换 shadow child，`undefined` 只移除 direct shadow 并保留 `effectLst` 与 glow/preset shadow/reflection/soft edge 等 sibling effects。Reader 对 malformed/ambiguous/wrong-namespace/effectDag/unsafe order 返回 `undefined`，setter 零 mutation 拒绝。PptxGenJS omitted 与 `type: 'none'` 映射 native `undefined`，legacy `offset` 对应 native `distance`；native 不复制其 zero falsy fallback、ignored rotate flag、hash/invalid/range passthrough 或 malformed inner closing tag。Generic effect stack、preset-shadow editing、custom shadow transforms，以及 image/text/table/chart/media 等其他 owner 的 shadow API 尚未支持。

### 门禁与实施顺序

每一行只有在 native `create/read/edit/delete/preserve/validate` 中适用的维度都有公开 API、单元测试、PptxGenJS public-output conformance、打包产物测试和真实 PPTX 兼容验证后才能标记完成。当前顺序固定为：preset shape/adjustments → shape fill/simple line/arrows/click hyperlink/simple shadow → custom geometry paths → custom formulas/handles/connections/text rectangle/evaluation → image/SVG → media 收尾 → chart → slide background/number/default color → master/layout/placeholder → advanced text → advanced table/`tableToSlides` → output/runtime helpers → peer-range full-suite audit。

Preset-shape geometry 通过 runtime-frozen `PRESET_SHAPE_TYPES` 和派生 `PresetShapeType` 暴露 178 个 canonical token。`SlideModel.addShape()` 默认 x/y/width/height 均为 1 inch，使用 direct `a:noFill` 与 empty `a:ln`；native transform 接受 EMU/OOXML angle，可通过 `inches()` / `degrees()` 转换。Options 只接受 ordinary 或 null-prototype object 的 own data properties，未知/inherited/symbol/accessor 字段和非法值在 mutation 前拒绝。新建 shape 与 live `ShapeModel` 保持 stable identity；same-value `presetType` assignment 是 exact no-op，type change 只 whole-replace direct geometry 并清除旧 adjustments，其他 transform/name/fill/line/arrows/effects/text/ext bytes 保留。Duplicate、rollback、六种格式、write/reopen、actual tarball Node/browser/types 以及锁定 PptxGenJS 4.0.1 的 public `ShapeType/addShape/write` 输出均有覆盖。PptxGenJS runtime 的 `folderCorner` 会写出不属于 OOXML `ST_ShapeType` 的无效 token；native 无损保留已有 bytes 但 strict preset snapshot 为 `undefined`，原生创建使用合法 `foldedCorner`。`custGeom` 不是 preset token，由 `addCustomShape()` / `customGeometry` 独立公开。

### Preset-shape adjustments

`ShapeAdjustment`、`AddShapeOptions.adjustments` 与 `ShapeModel.adjustments` 公开有序的 readonly `{ name, value }` direct guide 列表。Name 必须是唯一非空 XML-safe string；value 必须是 safe integer，并原样写为 `a:gd@fmla="val N"` 的 operand，不执行 shape-specific unit conversion、clamp 或 range guessing。输入必须是 dense ordinary array，entry 只能含 own data `name`/`value`，归一化 descriptor-safe、getter-free 且立即脱离 caller；getter 返回 detached deep-frozen snapshot。Setter whole-replace 整个 list，`[]` 保留 empty `a:avLst`，不接受 `undefined`；同一有序列表是 exact bytes/journal no-op。Reader 只接受唯一 namespace-correct direct `p:spPr/a:prstGeom/a:avLst`、direct same-namespace guides 和简单 `val` integer formula。Missing/repeated/wrong-namespace/duplicate/complex/malformed/unsafe state 读取为 `undefined`，编辑在 package 变化前抛 `ModelParseError`。不同 `presetType` 会重置 adjustments，同类型保留原 bytes；duplicate、rollback、六格式、write/reopen 与 stable identity 均已覆盖。

PptxGenJS 4.0.1 合法快捷字段最终输出可直接导入：`roundRect` 的 `rectRadius: 0.5`（w=4、h=2）得到 `adj=25000`；`angleRange: [270, 0]` 得到 `adj1=16200000`、`adj2=0`；fractional angles 按其 runtime 量化为 integer；`arcThicknessRatio: 0.5` 在有 angle range 的 block arc 上得到 `adj3=25000`。Native API 接受最终 guide list，因此保留 explicit zero、要求 number 且不实施 shortcut precedence。PptxGenJS 的 `rectRadius: 0` 与 zero thickness 会被 truthiness 丢弃，string 会转换，`rectRadius` 优先于 `angleRange`，没有 angles 时 thickness 被忽略，invalid input 还可写出 malformed/unsafe formula；adapter 无损保留这些 bytes，但 strict snapshot 对 unsupported state 返回 `undefined`。Custom geometry paths 使用独立 API；arbitrary guide formulas、handles、connection sites、custom text rectangle 与 geometry evaluation 尚未支持。

### Custom geometry paths

`CustomGeometryPoint`、`CustomGeometryCommand`、`CustomGeometryPathFill`、`CustomGeometryPath`、`CustomGeometry` 与 `AddCustomShapeOptions` 公开 strict custom path tree。`SlideModel.addCustomShape()` 从 blank presentation 直接创建 `a:custGeom`，`ShapeModel.customGeometry` 读取 detached deep-frozen snapshot 并 whole-replace 全部 geometry。Point/path extent/arc radius 是 direct EMU，arc angle 是 direct `1/60000°`；API 不推断 inch 或百分比，可显式调用 `inches()` / `degrees()`。六种 command 分支 `moveTo/lineTo/arcTo/quadraticBezierTo/cubicBezierTo/close`、多个 subpath、多个 path、empty command list、negative point、zero angle，以及 path `fill/stroke/extrusionOk` 均已覆盖。输入立即脱离 caller，unknown/missing/unsafe/非法顺序在 mutation 和 ID allocation 前拒绝；same-value 是 exact bytes/journal no-op，setter 不接受 `undefined` clear。

Custom ↔ preset 转换只替换 direct geometry，保留 live identity、name/transform、fill/line/arrows/shadow/hyperlink、text/effects/ext 与 relationship state。能力已覆盖 duplicate/source isolation、outer transaction rollback、六种 presentation formats、write/reopen、move/delete、unknown XML/opaque part preservation，以及 actual tarball Node/browser/types/CLI。非空 guide formulas、adjustment handles、connection sites 与 custom text rectangle 的 existing `a:custGeom` 会无损保留，但 strict snapshot 返回 `undefined`，replacement 零 mutation 拒绝；geometry evaluation 尚未公开。

transform height。PptxGenJS `rowH` 会把单项数组隐式广播、对 short/falsy item 混入 overall height 回退、忽略 long array 多余项，并在省略或冲突的 `h` 下生成 xfrm/rows 总高不一致；原生 API 严格拒绝这些模糊输入，且把 existing-deck 自动行高编辑作为 lossless extension。当前仍不支持 table-level fit creation、merge/colspan/rowspan 和 hyperlinks；table-level direction/border/margin/fill/valign getter/editor、diagonal/advanced borders、advanced fills、rich/multi-paragraph text 与 alignment、row insertion/deletion、table/cell creation styles、auto-page/repeated headers、内容测量与 layout recomputation 也尚未支持。

LibreOffice headless 可无修复打开 underline 文件，但当前会把 double/dash/wavy 和独立 underline color 降级显示为普通单实线；同一 PptxGenJS 4.0.1 对照文件表现一致。OOXML token 与颜色仍保持合法并可由支持这些样式的客户端读取。

LibreOffice headless 当前也不显示 run-level single/double strike；同一 PptxGenJS 4.0.1 对照文件表现一致。三个合法 `strike` token 仍保留在 OOXML 中。

PptxGenJS 4.0.1 的 `margin` tuple 注释声明 `[top, right, bottom, left]`，但 runtime 对非对称值会交换 top/left。本库采用公开文档顺序，并提供具名 `{ top, right, bottom, left }` 输入；adapter 仍会忠实读取 PptxGenJS 已生成的实际 OOXML。

文本框 `valign` 省略时原生 API 与 PptxGenJS 4.0.1 都显式使用 middle；top、middle、bottom 分别映射到 direct `bodyPr@anchor` 的 `t`、`ctr`、`b`。PptxGenJS 放在单个 rich-text run 上的 `valign` 不生效，本库也只在文本框级公开该选项。

文本框 `wrap` 省略或为 true 时原生 API 与 PptxGenJS 4.0.1 都写 `bodyPr@wrap="square"`，false 写 `none`。PptxGenJS 对非法值静默回退 true、并忽略单个 rich-text run 上的 `wrap`；本库只在文本框级接受严格 boolean。

文本框 `vert` 支持 `eaVert`、`horz`、`mongolianVert`、`vert`、`vert270`、`wordArtVert`、`wordArtVertRtl`，并原样映射到 direct `bodyPr@vert`。省略值不写属性，因此与显式 `horz` 不同；`shape.textDirection = undefined` 只清除 direct override。PptxGenJS 4.0.1 会把非法字符串原样写入，但本库创建和编辑严格拒绝，读取未知 token 返回 `undefined` 且保留原始 XML。普通文本框的 `textDirection` 别名以及 run 级 `vert` / `textDirection` 在 PptxGenJS 中不生效。

Table/table-cell `textDirection` 是独立的四值能力：`AddTableOptions.textDirection` 与 `AddTableCellOptions.textDirection` 都接受 `horz`、`vert`、`vert270`、`wordArtVert`，归一化后立即与 caller 脱离。创建时 table 值实体化到 cell value omitted 或 runtime-`undefined` 的 physical cells；任何 explicit cell 值优先，因此 cell `horz` 会阻断非水平 table default，但创建期仍省略 `tcPr@vert`。Resolved omitted/`undefined`/`horz` 都不写 direct attribute，三个非水平值写 exact physical-cell token；table omitted/`undefined`/`horz` 在无 cell override 的等价输入下生成相同 direction bytes。最终只保留 physical-cell direct state，不保留 table metadata，所以后续 clear 不会重新继承。Live snapshot、支持的无关 cell edit、duplicate、rollback、write 与 reopen 保持该 final state。`TableCell.textDirection` 只读取唯一 direct `tcPr` 上唯一、无 namespace 且精确合法的 token；`setCellTextDirection()` 以零基 physical row/cell index 编辑并保留 lossless direct-state 语义，因此显式 `horz` 写属性，`undefined` 只清除该属性。PptxGenJS 4.0.1 对 supported table/cell 创建、cell precedence 与 horizontal collapse 产生相同最终 direct state；runtime 放行的 `eaVert` 等类型外 token 严格读为 `undefined` 并原样保留，native 创建则在 mutation 前拒绝。Table-level direction getter/editor 仍未支持，并与 cell fit 独立。

Table/table-cell 水平对齐创建通过 `AddTableOptions.align` 与 `AddTableCellOptions.align` 复用严格的 `TextAlignment`：`left`、`center`、`right`、`justify` 分别映射到每个 cell 唯一单段落 direct `a:pPr@algn` token `l`、`ctr`、`r`、`just`，不在 `tcPr`、`bodyPr` 或 table metadata 写同名属性。table 值实体化到 omitted 或 runtime-`undefined` cell align，合法 cell 值优先；table align omitted 或 runtime-`undefined` 时保持原 bytes，也不合成 effective left。创建后仅保留 physical-cell direct state，不保留 default source，因此后续清除不会重新继承。`TableCell.horizontalAlignment` 只在唯一 direct `txBody` 中存在唯一 direct paragraph 和唯一 direct `pPr` 时读取无 namespace `algn`，精确映射四个 token；缺失、malformed、ambiguous、zero/multi-paragraph 状态返回 `undefined`，且不计算 effective default。`setCellHorizontalAlignment()` 以零基 physical row/cell index 写 canonical token，`undefined` 只清除 direct unqualified attribute；同值与 absent clear 是 exact no-op，unsafe structure 以零 mutation 拒绝，其他 paragraph/cell XML 保持不变。PptxGenJS 4.0.1 的合法 table/cell 值和 cell precedence 会物化为相同 direct state，并可由 adapter 精确读取和继续编辑；未知 table runtime 值仍会被 PptxGenJS 静默丢弃，而原生创建/编辑在 mutation 前抛 `TypeError`。已有 deck 编辑是 lossless native extension，因为 PptxGenJS 没有 existing-deck editor；rich/multi-paragraph cell alignment 仍未支持。

原生创建字段 `AddTableOptions.valign`、`AddTableCellOptions.valign` 和 snapshot 字段 `TableCell.verticalAlignment` 都复用严格的 `top`、`middle`、`bottom`，映射物理 cell 的 direct `tcPr@anchor="t/ctr/b"`，绝不读写 cell `bodyPr@anchor`。table 值会实体化到未提供 cell 值的位置，cell 值优先；两层都 omitted/`undefined` 时不写 anchor，并与等价 string cell 保持 byte-identical。`marL/marR/marT/marB` 后写 optional `anchor` attribute，再写 L/R/T/B borders 与 fill。live `TableModel` 会立即暴露解析后的每个 cell 值；创建后不保留 default source，所以 `setCellVerticalAlignment(..., undefined)` 清除 direct anchor 后不会重新继承。getter 要求唯一 direct `tcPr`、唯一无 namespace anchor 和精确 wire token，不合成 effective default；editor 不支持 `just/dist`。PptxGenJS 4.0.1 对合法 table/cell 值生成相同最终 direct state、实体化与覆盖顺序。PptxGenJS runtime 会透传类型外 token，adapter 严格导入为 `undefined`，而原生创建/编辑会直接拒绝。table-level getter/editor 仍未支持。

Table-cell `margins` 复用 point-based `TextBoxMargins` value shape，但只管理唯一 direct `tcPr` 上的 `marL/marR/marT/marB` signed-Int32 integer，不读取 `bodyPr@*Ins`、style 或 effective default。`AddTableOptions.margin` 与 `AddTableCellOptions.margin` 都接受 point scalar、精确 TRBL tuple、partial named object、`{}` 或 `undefined`；descriptor-safe、getter-free、ordinary/null-prototype-only 的归一化会立即脱离 caller。创建按 canonical top/bottom 3.6pt、left/right 7.2pt → table sides → cell sides 逐边解析；cell scalar/TRBL 覆盖四边，partial named 只覆盖提供边，omitted/undefined/empty cell margin 继承 table，omitted/undefined/empty table margin 维持原 bytes。最终只实体化 physical-cell direct attributes，不保留 table metadata；`TableCell.margins` 立即显示解析值，之后清除 cell 不会重新继承。zero、negative、positive、fractional point 均量化到最近 EMU，但 raw 必须落在 signed Int32。创建按 `marL/marR/marT/marB` attributes、optional anchor attribute、L/R/T/B border children、fill 的固定顺序输出。`setCellMargins()` 使用零基 physical row/cell index，接受相同 value shape 但执行 whole replacement，未提供的边会清除；合法同数值为 exact no-op，malformed direct token 可由合法值覆盖，或因该边缺省而清除。PptxGenJS 4.0.1 省略 margin 时写相同 narrow defaults，并以相同 table→cell 层级实体化最终 direct state；其遗留 runtime 以第一项 `<1` 按 inches、`>=1` 按 points。因此 native table/cell `7.2` 对等 PptxGenJS `0.1`，native `[3.6, 7.2, 10.8, 14.4]` 对等 PptxGenJS `[0.05, 0.1, 0.15, 0.2]`；native `0.1` 则有意表示 0.1pt 而不是 0.1in。adapter 忠实读取最终 EMU 并统一暴露 point，不逆推输入单位。table-level margin getter/editor 与 layout recomputation 仍未支持。

Table-cell `borders` 只管理选中物理 cell 唯一 direct `tcPr` 下同 prefix 的 `lnL/lnR/lnT/lnB`，以 partial `{ top, right, bottom, left }` snapshot 暴露 strict direct state。side value 是 `{ kind: 'none' }` 或 `{ kind: 'line', color, width, style? }`；width 为 `0..1584` point 并量化到 EMU，color 支持 strict sRGB/theme，style omitted/solid/dash 分别写 no direct dash、`solid`、`sysDash`。`AddTableOptions.border`、cell `options.border` 与 `setCellBorders()` 都接受 scalar、精确 TRBL tuple 或 partial named object。创建期采用 whole-value table→cell precedence：table 值只实体化到 normalized cell border 缺失的位置；任意非空 cell scalar/TRBL/named/none 完整阻断 table 值，未指定的 cell sides 仍是 canonical none 而不跨层继承。empty/all-undefined cell 值会继承 supplied table 值；empty/all-undefined table 值保持 omitted bytes。创建与编辑的 missing-side 语义有意不同：创建以 canonical 四条 direct noFill 为基线，tuple/named 未指定边保持 none；编辑器是 whole replacement，未指定边删除 direct element，`{}` / `undefined` 清除四边且不重新继承。所有 border/side/color 输入都 descriptor-safe、getter-free、ordinary/null-prototype-only 并立即深度脱离。OOXML 始终按 L/R/T/B 写出，四边之后才写 optional cell fill。getter 独立省略 malformed/unsupported side，不读取或近似 diagonal、其他 dash、gradient/pattern line、compound/cap/join/arrow/effect，也不计算 adjacent shared-edge 或 effective table style；这些状态在无关 mutation 中原样保留。对 table/cell explicit scalar/TRBL none、sRGB line、solid/dash、scalar zero width 和 cell whole-value override，原生创建与 PptxGenJS 4.0.1 的最终 snapshot、geometry、margins、fill 和 direct side state 对等。差异是 native empty border 表示无有效 layer，而 PptxGenJS `{}` 默认 `666666`/1pt/solid 且 cell `{}` 会阻断 table default；native omitted style 不写 direct dash，而 PptxGenJS 默认 direct solid；native scalar/TRBL zero 都保留 zero，而 PptxGenJS TRBL item `pt: 0` 变成 1pt；native tuple 必须 dense 且恰好四项，PptxGenJS runtime short tuple 会把 missing sides 实体化为 none；native 额外支持 named sides 和 theme color。adapter 只读取最终 L/R/T/B XML，不逆推输入层级。table-level getter/editor、diagonal/advanced line/transparency、shared-edge layout 与 layout recomputation 仍未支持。

Table-cell `fill` 只读写选中物理 cell 唯一 direct `tcPr` 下的 fill choice，以 `{ kind: 'none' }` 区分 direct `a:noFill`，以 `{ kind: 'solid', color, transparency? }` 表达 strict sRGB/theme solid fill 和可选 direct alpha。`AddTableOptions.fill` 与 `AddTableCellOptions.fill` 复用这个 descriptor-safe、getter-free、ordinary/null-prototype-only value，并立即与 caller 深度脱离。table fill 是 whole-value 创建默认：只实体化到 cell fill 为 omitted/`undefined` 的 physical cells，cell solid/none 完整覆盖；omitted/runtime-undefined table fill 保持原 bytes，empty fill object 非法。OOXML 固定按 margins attributes、optional anchor、optional direction、L/R/T/B borders、fill 输出。live `TableModel` 会立即返回 resolved detached `TableCell.fill`；创建后不保留 table default，因此 `setCellFill()` 的 replace/clear 只作用于零基 physical cell 的最终 direct state，`none` 写 direct noFill，`undefined` 删除 direct choice且不会重新继承。transparency 是 finite `0..100` 百分比，量化到 `0.001%`；omitted 不写 alpha，explicit zero 写完全不透明 alpha。getter 只接受同 prefix、无歧义的 direct noFill/solidFill，不把 border/text descendants 当成 cell fill，也不解析 effective table style；其他 fill 类型在无关 mutation 中原样保留。PptxGenJS 4.0.1 对 supported table solid fill 与 cell solid override 生成相同 final direct cell state，但会把 omitted 与 `type: 'none'` 都折叠为没有 direct fill，并把 explicit zero transparency 折叠为没有 alpha；native direct none 和 explicit zero 因此保留可见 direct-state 差异。runtime 越界值可生成非法 alpha，adapter 保留 XML 但 strict snapshot 返回 `undefined`。创建时 align/border/fill/fit/margin/textDirection/valign 之外的 cell options、table-level direction/fill/border getter/editor、diagonal/advanced border、gradient/pattern/picture/group fill 与 layout recomputation 仍未支持。

Table-cell `textFit` 复用 `none`、`shrink`、`resize`。原生 plain-text cell 可通过 `AddTableCellOptions.fit` 创建 direct fit：omitted、runtime `undefined` 与 `none` 生成 byte-identical self-closing `bodyPr` 且 immediate snapshot 都是 `undefined`；`shrink` / `resize` 分别写唯一 direct `normAutofit` / `spAutoFit` 并立即 snapshot。创建不写 `noAutofit`、不保留 table metadata、不计算最终 font scale，也不测量内容或重算 cell/table geometry；fit child 与 `tcPr@vert` direction 独立。Getter 只读取唯一 direct `txBody/bodyPr` 中唯一 supported fit child，既有 `noAutofit` 映射为 `none`，缺失或 malformed 状态返回 `undefined`。`setCellTextFit()` 以零基 physical row/cell index 编辑；shrink/resize 写上述 child，none/`undefined` 都移除 direct choice、不恢复创建输入且不新增 `noAutofit`，同模式赋值保留 PowerPoint 已计算的 scale metadata。Table-level fit creation/default/getter/editor 均未支持。PptxGenJS 4.0.1 的 `TableCellProps` / `TableProps` 没有 fit API，runtime 透传的 `fit`、`autoFit`、`shrinkText` 均被忽略并生成 fit-less `bodyPr`；native shrink/resize creation 是明确扩展，不作为 PptxGenJS parity 声明。

LibreOffice headless 可正确显示 table-cell `horz`、`vert` 和 `vert270`，但当前把 `wordArtVert` 显示为水平文字；同一 direct OOXML 的 PptxGenJS 4.0.1 对照文件表现完全一致，`tcPr@vert="wordArtVert"` 仍保持合法并可由 PowerPoint 等支持该模式的客户端读取。

文本框 `fit` 的 omitted/none 都不写 direct child，shrink 写 `bodyPr/a:normAutofit`，resize 写 `bodyPr/a:spAutoFit`。`shape.textFit` 也读取既有唯一 `a:noAutofit` 为 none；none 或 `undefined` 清除 direct fit choice，同模式 shrink/resize 赋值保留 PowerPoint 已计算的 `fontScale` / `lnSpcReduction`。PptxGenJS 对非法 outer 值和 run-level fit 静默忽略，本库严格拒绝非法原生输入；adapter 仍兼容 deprecated outer `shrinkText` / `autoFit` 输出。最终缩放比例可能要由 PowerPoint 在编辑文字或改变 shape 大小时动态重算。

文本语言通过 `AddTextOptions.lang` 提供 plain/rich 创建默认值，`RichTextRunStyle.lang` 可覆盖单个 run。省略时 run 与 `endParaRPr` 使用 `en-US`；显式 outer/run 语言在 run 上同时写 `altLang="en-US"`，`endParaRPr` 只跟随 outer 值。getter 只暴露非空 direct `rPr@lang`，不解析 `altLang` 或 master/layout 继承。原生 API 拒绝非 string、空 string 和非法 XML 控制字符，并安全转义 attribute metacharacters。PptxGenJS 4.0.1 的 falsy fallback 仍由 adapter 输入兼容；未转义字符串产生的无效 XML 不属于兼容承诺。

Rich run `transparency` 使用 `0..100` 百分比：0 完全不透明，100 完全透明，并量化到最近 `0.001%`（`alpha = Math.round((100 - transparency) * 1000)`）。省略字段不写 alpha，显式 0 写 direct `alpha val="100000"`，因此本库可区分 absence 与 explicit opaque；PptxGenJS 4.0.1 因 truthy 判断会把 0 与 omitted 都省略。没有显式 run color 时本库沿用默认 `schemeClr tx1`，PptxGenJS 则实体化 direct black，effective transparency 相同。该字段只控制文字主 `rPr/solidFill`，不影响 outline、glow、highlight、underline、shape 或 table-cell fill。getter 只接受唯一 direct solid fill、唯一合法 sRGB/theme color 和唯一严格 integer alpha，不解析继承或其他/mixed color transform。

Paragraph 左右边距分别通过 `AddTextOptions.paragraphMarginLeft` / `paragraphMarginRight` 提供 plain/rich 创建默认，`RichTextParagraph.marginLeft` / `marginRight` 使用 point 提供本地 number override，`false` 抑制默认或清除对应 direct `pPr@marL` / `marR`。getter 仅读取 `0..51206400` 的 direct integer EMU，不解析继承。普通段落缩进通过 `AddTextOptions.paragraphIndent` 提供创建默认，`RichTextParagraph.indent` 接受 `-4032..4032` point：正值是 first-line indent，负值是 hanging indent，`false` 抑制默认或清除 direct `pPr@indent`。新建普通段落保留 canonical direct zero；setter omission 清除已有 direct 值。getter 仅读取 `-51206400..51206400` 的 direct signed integer EMU。direct bullet/numbering/picture bullet 拥有 `marL` 与 `indent`，因此 getter 不重复暴露 `marginLeft` 或 ordinary `indent`，同 paragraph 的 numeric left margin/ordinary indent 与 active bullet 也在 mutation 前拒绝；`marR` 与列表缩进独立，可在普通、bullet 或 numbering paragraph 上读取和编辑。左右字段与 indent sign 始终映射物理 OOXML，不因 RTL 交换。PptxGenJS 4.0.1 没有普通 paragraph 左右边距或 first-line/hanging indent 公开选项；其普通 paragraph direct `marL="0"` / `indent="0"`、列表 `marL` / negative `indent` 和默认缺失 `marR` 的输出均可正常导入。

Presentation RTL 通过 `CreatePresentationOptions.rtlMode` 创建，并可由 `document.rtlMode` 读取、编辑和清除。getter 只读取 direct `p:presentation@rtl`，接受 `1/true/on` 与 `0/false/off`；未知或 descendant token 不会伪造全局状态。true/false 分别写 `1` / `0`，undefined 清除 direct attribute。PptxGenJS 4.0.1 的 true 与 truthy 非 boolean 都写 `1`，false/omitted 都省略；本库严格拒绝非 boolean，显式 false 写 `0`，effective behavior 相同且 direct intent 可逆。全局 RTL 不改写 paragraph `pPr@rtl`、`bodyPr@rtlCol`、default text style、alignment 或 run 顺序。

段落 RTL 通过 `AddTextOptions.rtlMode` 提供 plain/rich 创建默认值，`RichTextParagraph.rtl` 可逐段覆盖。true/false 分别写 direct `pPr@rtl="1"` / `"0"`；setter 中省略字段会清除 direct override。getter 只接受 `1/true/on` 与 `0/false/off`，未知 token 返回 `undefined` 并在无关编辑中原样保留。该能力不读取或修改 `bodyPr@rtlCol` 或 presentation-level RTL，也不自动交换 alignment。PptxGenJS 4.0.1 的 valid outer true 多段输出可直接导入；其 run-level `rtlMode` 会在同一 paragraph 中插入重复且位置非法的 `pPr`，因此本库不公开 run-level RTL。

原生创建会生成可重新打开和验证的 master/layout/theme 关系链，不通过 adapter，也不在运行时安装或调用 PptxGenJS。
