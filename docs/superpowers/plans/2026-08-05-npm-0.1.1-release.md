# npm 0.1.1 `next` release plan

**Goal:** Publish the verified aggregate package as `@jiayunxie/pptx@0.1.1` on the npm `next` dist-tag with provenance, while keeping internal workspace packages unpublished and explicitly documenting the remaining client-certification boundary.

**Release scope:** All workspace manifests remain lockstep at `0.1.1`; only `packages/pptx` is public. The `@pptx/*` packages and plugins are implementation-only workspaces and must be marked private. This is a technical-preview release, not a claim that Windows PowerPoint, macOS Keynote, or Google Slides certification has passed.

## Tasks

1. Add a single version-update/check script, bump the lockstep version to `0.1.1`, and remove release-version literals from the npm workflow.
2. Mark every internal workspace package private so only `@jiayunxie/pptx` can be published.
3. Update release notes and current-version documentation without rewriting historical implementation plans.
4. Run version checks, focused tests, PptxGenJS parity audit, full checks, performance gate, build, pack, tarball smoke, and package-content review.
5. Review the complete diff, commit, push `main`, create and push annotated tag `v0.1.1`.
6. Publish the exact verified tarball through the trusted-publishing workflow with the `next` tag, then verify registry version, dist-tag, provenance/integrity metadata, and a fresh consumer install.

## Success criteria

- `@jiayunxie/pptx@0.1.1` is visible on npm and `next` points to it.
- The registry-installed package passes import, browser export, CLI, types, and presentation create/write/reopen smoke checks.
- The published artifact matches the reviewed release commit and tag.
- Release reporting clearly retains the three outstanding real-client certification items.
